# Infinite Canvas 跨电脑同步

Infinite Canvas 的画布和图片默认保存在浏览器 IndexedDB，不会因为 GitHub 仓库更新而自动同步。仓库只保存经过检查的画布导出文件；API Key、Connect token、WebDAV 密码和原始 IndexedDB 不应提交。

## 在当前电脑导出

1. 打开 `https://canvas.best/canvas`，在目标画布上点击“导出”。
2. 把导出的 JSON 放到 `canvas-sync/exports/`。
3. 用仓库脚本清理敏感字段：

   ```bash
   node scripts/sanitize-canvas-export.mjs \
     canvas-sync/exports/画布.json \
     canvas-sync/exports/画布.safe.json
   ```

4. 检查脚本报告，确认没有 API Key、token、密码或私人配置后，再提交 `*.safe.json`。

如果导出时出现 `Failed to fetch`，先确保本机 Canvas Agent 正在运行，并在网页右侧显示“已连接”；不要改为读取或复制浏览器 IndexedDB 文件。

## 在其他电脑导入

1. 拉取仓库：

   ```bash
   git clone https://github.com/chufeng/NewJDWeb.git
   cd NewJDWeb
   ```

2. 打开 `https://canvas.best/canvas`，点击“导入画布”，选择仓库中的 `canvas-sync/exports/*.safe.json`。
3. 在该电脑单独启动本地 Agent：

   ```bash
   npx -y @basketikun/canvas-agent
   ```

4. 在网页中连接新的 `Local URL`。API Key 需要在这台电脑单独配置；不要把 API Key 写入导出文件或 GitHub。

## 自动同步选项

如果不想每次手动导出/导入，可以在画布“配置 → WebDAV”配置自己的 WebDAV。WebDAV 会同步画布、资产、生成记录和媒体文件，但不会同步 AI API Key。GitHub 适合版本管理安全导出文件，不适合存放原始 IndexedDB。

## 当前婚礼开场画布内容基线

仓库目前没有可提交的安全画布导出文件，因此下面内容是根据已确认的策划信息整理的“重建基线”，不是 IndexedDB 的副本。其他电脑需要先阅读本节，再按四条时间线重新创建画布节点；不要把这份文档当作 API 配置或素材文件。

### 故事核心

两个人在上海多次处于同一现场，却一次次擦肩而过，直到 2020 年同好饭局才真正相遇。画面建议让四条线同时推进，前三条依次错过，第四条在最后一刻相遇。

### 四条时间线

1. **2009 · 上海日全食：科技馆与旅游大巴**
   - 女方在旅游大巴上经过上海科技馆，并从车上看到了日全食。
   - 男方在上海科技馆等待并观看日全食；大巴经过时两人正好错开。
   - 画面重点：同一片天象、车窗与科技馆两个视角、空间上的擦肩而过。

2. **2010 · 上海世博会：沙特馆排队**
   - 两人都提到想去沙特馆。
   - 沙特馆排队约 4 小时；男方选择排队，女方看到队伍太长放弃。
   - 两人在队伍入口或人流中擦肩而过，却没有相遇。

3. **2018 · BML 演唱会：场外粉丝交流**
   - 两人都在 BML 现场，场外有许多粉丝交流。
   - 两人差点眼神对上，但男方被朋友拉去聊天，女方也被闺蜜拉去交流。
   - 画面重点：同一入口、视线被人群和朋友打断、近在咫尺却错过。

4. **2020 · 同好饭局：最后一刻相遇**
   - 男方打羽毛球后很晚才到，其他人差不多吃完、准备离开。
   - 他在最后一刻赶到，第四条线没有再次错过，两人终于真正相遇。
   - 画面重点：空桌、起身告别的人、刚到门口的男方、留下来的女方和相遇瞬间。

### 人物素材与生成约束

- 使用结婚照作为本机参考图来保持两人的身份特征；参考照片只在本机上传，不放进 GitHub。
- 为男方和女方分别制作各年代的常服三视图/角色素材，服装采用对应年代上海主流日常穿着。
- 女方早期（2009、2010）造型保留小侧辫，并比后期略圆润；所有人物保持自然真实比例。
- 只使用 `gpt-image-2`；不要自动切换到 `super`、`4k` 或 Grok 变体。
- 已知较稳定的工作台参数是：单张、质量“中”、比例 2:3；优先走 `/v1/images/generations`。参考图编辑走 `/v1/images/edits`，但画布端此前出现过 `Failed to fetch`，不要连续重试。
- 每次只生成一个节点，确认结果后再继续下一个；失败时先检查代理、模型映射和 Agent 日志，避免重复扣费。

### 画布重建与排版要求

请根据本节重建画布，而不是凭空另写一套剧情：

1. 先建立四个年代系列，按 2009、2010、2018、2020 从上到下各占一行。
2. 每行按“场景说明 → 人物参考/常服素材 → 生图配置 → 生成结果 → 备注”从左到右排列，行与行之间留出足够空白，禁止节点重叠。
3. 先创建文本和布局节点，再逐个生成素材；每完成一张就检查人物身份、年代服装、小侧辫和画面构图。
4. 2020 行要明确标记为“差点错过但最终相遇”，作为前三条错过的情绪收束。
5. 如果要同步回 GitHub，必须先导出并运行安全清理脚本，只提交审核过的 `canvas-sync/exports/*.safe.json` 和本说明文档；原始导出、IndexedDB、API Key、Connect token、Cookie、上传照片和生成结果 URL 均不得提交。
